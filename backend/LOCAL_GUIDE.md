# 로컬 실행과 업무 안내

## 실행

JDK 21이 필요합니다. Gradle은 저장소의 Wrapper를 사용합니다. 반드시 `backend`를 작업 디렉터리로 사용하세요. 상대 경로 DB를 사용하므로 다른 디렉터리에서 실행하면 별도의 DB가 열릴 수 있습니다.

Windows PowerShell:

```powershell
cd backend
.\gradlew.bat build --no-daemon
.\gradlew.bat bootRun
```

Linux/macOS:

```bash
cd backend
bash gradlew build --no-daemon
bash gradlew bootRun
```

브라우저에서 `http://localhost:8081`을 엽니다. 종료는 실행 터미널의 Ctrl+C입니다. 서버가 이미 실행 중이면 같은 H2 파일을 여는 서버나 DB 편집기를 추가로 실행하지 마세요.

## 본인 PC의 첫 관리자

공용 기본 비밀번호는 없습니다. 서버를 종료한 뒤, `backend`에서 실행합니다.

```powershell
.\scripts\bootstrap-admin.ps1
```

```bash
bash scripts/bootstrap-admin.sh
```

아이디에 `admin`을 입력합니다. 이미 가입한 계정이라면 **그 계정의 기존 비밀번호**를 입력해야 관리자 권한으로 올라갑니다. 신규 계정이면 이메일과 새 비밀번호를 입력합니다. 비밀번호는 터미널에 표시되지 않으며 명령행 인자로 전달하지 않습니다. 이미 관리자가 있는 DB에서는 이 초기 설정을 거절합니다. 기존 관리자가 사용자 관리 화면에서 임명해야 합니다.

서버를 다시 실행하고 로그인합니다. 관리자 화면에서 부서를 생성하고 자신에게도 부서를 배정하세요. 부서 문서 작성에는 소속 부서가 필요합니다. 이 절차는 명령을 실행한 PC의 DB에 적용됩니다.

## 처음부터 배포까지

1. 회원가입한 사용자에게 관리자가 부서·직급·보안 등급을 배정합니다. 가입만으로 관리자 권한이나 기밀 접근 권한을 얻지 않습니다.
2. 홈 → 프로젝트 → 프로젝트 생성. 일반 사용자는 소속 부서의 과장 이상, 관리자는 담당 부서를 지정하여 생성합니다. 생성자는 프로젝트 책임자입니다.
3. 참여자 화면에서 책임자·연구개발·품질·보안·작성자·열람자 역할을 배정합니다. 직급·보안 등급은 프로젝트 역할과 별도로 검사합니다.
4. 프로젝트 개요에서 문서를 작성합니다. 초안을 저장한 뒤 상세 화면에서 첨부파일을 올리고, 초안 편집 화면에서 제출합니다. 일반 부서 문서는 홈의 문서 작성에서 시작합니다.
5. 일반 작성자의 문서는 독립된 검토자가 승인합니다. 기밀·제한 문서는 기술 승인 뒤 별도 보안 승인을 받습니다. **관리자가 작성·제출한 문서는 부서/프로젝트와 보안 등급에 관계없이 즉시 승인**되며 `AUTO_APPROVED` 의견과 감사 기록을 남깁니다. 관리자도 초안 저장만 하면 초안으로 남습니다.
6. 제출 후에는 본문과 첨부파일을 직접 바꿀 수 없습니다. 새 버전을 생성하면 기존 내용과 첨부 구성을 복사한 초안이 생깁니다. 과거 승인·반려·의견은 해당 버전에 남습니다.
7. 연구개발 변경 요청은 승인된 기준 버전을 선택하여 등록하고 담당자를 배정합니다. 동일 문서의 승인된 후속 버전과 처리 근거를 연결해 해결하거나 사유를 남겨 거절합니다.
8. 품질 담당자는 시험 기준을 등록하고 적합한 항목을 체크한 뒤 시험 근거를 기록합니다. 미체크 항목이 있으면 부적합 보고서가 생성됩니다. 시정 후 원 시험을 지정해 재시험하고, 적합 재시험과 시정 조치 근거를 연결해 부적합을 닫습니다.
9. 보안 담당자가 현재 문서 구성의 보안 검토를 승인합니다. 문서 작성자와 품질·보안 판정자는 분리되며 품질과 보안도 서로 다른 사람이 수행합니다. 관리자 문서 즉시 승인 정책이 이 프로젝트 배포 검사를 생략하지는 않습니다.
10. 책임자가 프로젝트를 배포 검토 상태로 전환합니다. 최종 배포 탭에 표시되는 차단 사유를 해결하고 수신자 로그인 아이디와 배포 설명을 입력합니다. 기본 필수 문서는 설계·시험 보고서·보안 검토서 각 1건이며 프로젝트 개요에서 조정합니다.
11. 배포 시 정확한 문서 버전과 수신자를 고정합니다. 지정 수신자는 배포 상세에서 ZIP을 내려받습니다. 문서나 시험 기준이 바뀌면 새 구성에 대한 품질·보안 검토가 필요합니다. 책임자의 배포 회수 이후에는 추가 다운로드가 차단됩니다.

최소 3명의 계정(관리자 문서 작성자, 품질 담당자, 보안 담당자)으로 전체 배포 흐름을 수행할 수 있습니다. 일반 작성자 문서는 별도의 기술 검토 권한을 가진 계정도 필요합니다. 같은 계정이 여러 역할을 차례로 맡아 자기 결과를 승인하는 방식은 허용하지 않습니다.

## 일상 업무

- 홈 검색·최근 문서, 문서 목록의 제목/작성자/상태/분류/정렬/보관 필터를 사용합니다. 페이지 이동 시 검색 조건이 유지됩니다.
- 부서 생성 즉시 부서 탭이 나타납니다. 부서 문서·프로젝트·부서 공지를 한 화면에서 확인합니다. 전체 공지는 별도 전체 공지 메뉴에 있습니다.
- 내 업무는 본인 초안·반려, 기술 검토, 보안 검토 대상을 권한에 맞게 표시합니다. 알림은 업무 담당자와 작성자·수신자에게 저장됩니다.
- 임시 접근은 문서 번호와 사유로 요청합니다. 승인 유효기간 중에도 최소 직급과 보안 등급을 충족해야 하며 편집·검토 권한을 부여하지 않습니다.
- 내 계정에서 비밀번호를 변경합니다. 분실 시 관리자가 본인 확인 후 복구 관리에서 30분 유효 일회용 링크를 발급합니다. 사용·만료된 링크는 다시 쓸 수 없습니다. 비밀번호 변경/복구 후 기존 세션은 다시 로그인해야 합니다.
- 부서를 폐쇄할 때 사용자·문서·프로젝트·공지를 운영 중인 부서로 이관합니다. 데이터는 삭제하지 않습니다.

## 데이터와 백업

| 데이터 | 기본 위치 또는 설정 |
| --- | --- |
| 사용자·문서·업무 DB | `data/aegisvault.mv.db` / `spring.datasource.url` |
| 첨부 원본 | `local/files` / `app.files.path` |
| 감사 HMAC 키 | `local/audit.key` / `app.audit.key-file` |
| 마이그레이션 전 자동 백업 | `local/backups` / `app.backup.path` |
| 애플리케이션 로그 | `logs/aegisvault.log` / `logging.file.name` |

Flyway V1/V2가 기존 스키마를 갱신하고 Hibernate가 구조를 검증합니다. 기존 로컬 H2 DB를 갱신하기 전 일관된 DB ZIP 백업을 만들며 감사 키가 있으면 함께 복사합니다. 백업 실패 시 갱신을 중단합니다. 데이터 초기화나 테스트 통과를 위한 `create-drop` 운영 설정을 사용하지 않습니다.

정기 백업은 서버를 종료한 뒤 **DB·첨부 디렉터리·감사 키를 함께** 복사하세요. 마이그레이션 백업에는 첨부파일이 포함되지 않습니다. 복구는 서버 종료 상태에서 같은 시점의 DB·파일·키를 별도 경로에 먼저 복원해 확인한 뒤 전환합니다. 기존 감사 기록이 있는데 키가 없으면 서버는 새 키로 대체하지 않고 시작을 거절합니다. 키와 백업을 Git에 올리지 마세요.

첨부는 PDF·PNG·JPEG·TXT·CSV, 파일당 최대 10 MiB이며 실제 형식과 해시를 확인합니다. 초안에서 제거된 파일은 다른 버전에서 참조 중이면 유지됩니다. 참조 없는 저장 파일은 24시간 유예 후 정리합니다.

## 검증 범위와 운영 경계

테스트는 격리된 메모리 DB 및 임시 파일 DB를 사용합니다. 문서 권한·동시 버전 생성·중복 배포·동시 복구 토큰 사용·세션 무효화·감사 변조·레거시 데이터 이전을 포함합니다. 보고서는 `build/reports/tests/test/index.html`입니다.

로컬 전체 업무를 대상으로 구현했습니다. 다중 서버·대규모 트래픽에 대한 부하 검증이나 외부 배포는 수행하지 않았습니다. 서버/도메인/메일 서비스가 정해지면 운영 DB, HTTPS, 비밀키 보관, 외부 백업, 모니터링, SMTP 연동을 배포 환경에 맞게 구성해야 합니다.

- 워터마크는 문서 상세와 내보낸 문서 HTML에 사용자·시각·버전을 표시합니다. ZIP의 원본 첨부파일 자체를 변환하거나 워터마크 처리하지 않습니다. 다운로드된 사본을 원격 삭제하거나 캡처를 막는 DRM 기능은 아닙니다.
- 감사 체인은 개별 기록 변경·삭제·순서 변경을 검증합니다. DB와 키를 함께 과거 백업으로 되돌리는 공격까지 탐지하려면 외부 보관 기준점이 필요합니다.
- 파일 형식·무결성 검사는 백신 검사를 대신하지 않습니다. 악성코드 스캐너와 외부 메일 발송은 아직 연결하지 않았습니다.
- 기본 수신 주소는 `127.0.0.1`, 화면 시각은 UTC입니다. 공용 인터넷에 직접 열기 위한 설정은 포함하지 않았습니다.
