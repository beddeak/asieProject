# AegisVault 통합 업무 설계

## 범위와 실행 기준

기존 Java 21 / Spring Boot / Thymeleaf 모놀리스를 유지한다. 로컬에서 모든 업무 흐름을 실행하며, 외부 공개 서버와 메일 서비스는 아직 정해지지 않았다. 기존 사용자·부서·문서를 보존한다.

별도 규칙 클래스를 남발하지 않는다. 상태 변경은 해당 엔티티 메서드, 권한은 여러 진입점에서 공유하는 접근 정책, 조회는 목록 DTO와 DB 페이지네이션으로 구현한다. 문서 본문에 임의의 글자 수 제한을 다시 도입하지 않는다.

## 핵심 관계

- 프로젝트는 부서에 속하며 참여자마다 책임자·연구개발·품질·보안·작성자·열람자 역할을 가진다.
- 문서는 부서 문서 또는 프로젝트 문서이며, 분류·열람 직급·보안 등급을 가진다. 프로젝트 문서는 참여 자격을 추가로 검사한다.
- 버전은 초안에서만 편집할 수 있다. 제출 후 내용과 첨부파일을 변경하려면 새 버전을 만든다. 승인·의견·시험·보안 검토·배포는 버전 또는 버전 집합에 연결한다.
- 부서/참여 범위의 임시 열람 예외는 승인된 유효기간 안에서만 적용한다. 직급과 보안 등급은 계속 검사한다.
- 부서 공지와 전체 공지는 동일한 공개 범위 개념으로 조회하며 기존 부서 공지 주소도 유지한다.

## 업무 순서

1. 프로젝트 생성 → 참여자·필수 문서·품질 체크리스트 구성
2. 문서 초안·첨부 → 검토 요청 → 독립된 검토자의 승인/반려·의견
3. 필요한 보안 등급의 문서는 별도 보안 승인
4. 변경 요청 → 승인 → 새 버전 연결 → 재검토 후 해결
5. 현재 문서 버전 집합에 대한 품질시험 → 부적합·시정조치·재시험
6. 현재 버전 집합에 대한 보안 검토
7. 배포 게이트에서 필수 문서·승인·미해결 변경/부적합·품질/보안 결과를 재검사
8. 수신자와 정확한 버전을 고정한 배포 기록 생성 → 수신자 열람·다운로드 → 필요 시 회수

## 일관성과 보안

- 버전 번호 생성과 배포 판단은 DB 잠금으로 직렬화한다. 프로젝트 변경은 프로젝트 잠금 다음 문서 잠금 순서를 지킨다.
- 오래된 편집 폼은 낙관적 버전으로 감지하여 덮어쓰지 않는다.
- 새 버전이나 첨부 구성 변경은 이전 품질·보안 검토를 새 배포의 근거로 재사용할 수 없게 한다.
- 다운로드는 저장 경로를 받지 않고 첨부 ID로 접근 권한을 다시 확인한다. 파일은 정적 리소스 경로 밖에 저장한다.
- 감사 기록은 업무 변경과 함께 저장하며, 로그인 실패·권한 거부는 별도 트랜잭션으로 보존한다. HMAC 연결과 마지막 기록 기준점을 검증하고, 검증 범위와 한계는 운영 문서에 명시한다.
- 비밀번호 재설정 토큰은 해시로 저장하고 만료·일회 사용을 검사한다. 로컬에서는 관리자가 본인 확인 후 재설정 링크를 전달하는 흐름을 제공한다.
